🎯 PASO A PASO DE IMPLEMENTACIÓN
══════════════════════════════════════════════════════════════════════════════

PASO 1: INCLUIR EN HTML (CRÍTICO)
   
   En tu archivo Master.master o en el <head> ANTES de otros scripts:
   
   <script src="/Content/assets/js/securityHelper.js"></script>
   <script src="/Content/assets/js/apiHelper.js"></script>
   

PASO 2: CONFIGURAR CSP EN SERVIDOR
   
   En Global.asax - Application_BeginRequest():
   
   Response.Headers.Add("Content-Security-Policy", 
       "default-src 'self'; script-src 'self' ....");
   
   VER: ServerSecurityHelper.cs para ejemplo completo
   

PASO 3: VALIDAR FORMULARIOS
   
   ANTES:
   var nombre = $("#txtNombre").val();
   fetchDataArr(5, { nombre: nombre }, 9, function(response) { ... });
   
   DESPUÉS:
   const rules = {
       nombre: { type: 'string', required: true, minLength: 5 }
   };
   const validation = validateAndPrepareData({ nombre: $("#txtNombre").val() }, rules);
   if (!validation.valid) { showMsg(validation.errors.join('\n'), 'error'); return; }
   const secureData = prepareSecureData(validation.data, AUTOMATA_SLAYER_VERSION);
   fetchDataArr(5, secureData, 9, function(response) { ... });
   

PASO 4: CODIFICAR SALIDA
   
   ANTES:
   $("#tabla").append(`<td>${item.descripcion}</td>`);
   
   DESPUÉS:
   $("#tabla").append(`<td>${encodeHTML(item.descripcion)}</td>`);
   

PASO 5: VALIDAR EN SERVIDOR
   
   En tu controlador C#:
   var validation = ServerSecurityHelper.ValidateFormAlineacion(...);
   if (!validation.IsValid) return Json(new { flag = false, msg = validation.GetErrorString() });
   
   SIEMPRE usa Parametrized Queries:
   cmd.Parameters.AddWithValue("@nombre", txtNombre); // ✅ CORRECTO
   // NO HACER: query = "SELECT * FROM users WHERE nombre = '" + nombre + "'"; // ❌ PELIGRO


📚 FUNCIONES PRINCIPALES POR CATEGORÍA
══════════════════════════════════════════════════════════════════════════════

VALIDACIÓN:
  ├─ sanitizeInput(text)               → Limpia caracteres peligrosos
  ├─ isValidNumber(value, min, max)    → Valida números con rango
  ├─ isValidEmail(email)               → Valida emails
  ├─ isValidDate(date)                 → Valida fechas YYYY-MM-DD
  ├─ isAlphanumeric(text)              → Valida solo letras y números
  └─ validateAndPrepareData(data, rules) → Valida múltiples campos a la vez

CODIFICACIÓN:
  ├─ encodeHTML(text)                  → Para mostrar en HTML
  ├─ encodeAttribute(text)             → Para atributos HTML
  └─ encodeURL(url)                    → Para parámetros URL

SEGURIDAD:
  ├─ prepareSecureData(data, version)  → Prepara datos con protección
  ├─ generateDataChecksum(data)        → Verificar integridad
  ├─ getRecommendedCSP()               → Obtiene directiva CSP
  ├─ supportsCSP()                     → Verifica soporte navegador
  └─ monitorCSPViolations()            → Escucha intentos de ataque


🧪 PRUEBAS DE SEGURIDAD QUE DEBES HACER
══════════════════════════════════════════════════════════════════════════════

✓ PRUEBA XSS:
  Escribe en campo de texto: <script>alert('XSS')</script>
  Esperado: Se muestra el texto, NO se ejecuta

✓ PRUEBA SQL INJECTION:
  Escribe en campo año: 2020'; DROP TABLE users --
  Esperado: Mensaje de validación (error)

✓ PRUEBA MANIPULACIÓN HTML:
  Abre F12, cambia data-id="123" a data-id="999" en un botón
  Esperado: Servidor rechaza por permiso, no por cliente

✓ PRUEBA CSP:
  Abre consola (F12), busca "securitypolicyviolation" en logs
  Esperado: Se registran violaciones de CSP

🔗 FLUJO DE SEGURIDAD COMPLETO
══════════════════════════════════════════════════════════════════════════════

Usuario escribe en formulario
         ↓
JavaScript VALIDA con validateAndPrepareData()
         ↓ (Si hay error, muestra mensaje y STOP)
JavaScript CODIFICA salidas con encodeHTML()
         ↓
JavaScript envía datos con fetchDataArr() + versión + checksum
         ↓
Servidor VALIDA nuevamente con ServerSecurityHelper
         ↓ (Si hay error, rechaza y registra intento)
Servidor VERIFICA permisos del usuario
         ↓ (Si no tiene permiso, rechaza y registra)
Servidor EJECUTA query con Parametrized Statements
         ↓ (Nunca concatena strings)
Servidor RESPONDE con datos
         ↓
JavaScript CODIFICA respuesta con encodeHTML()
         ↓
Usuario VE datos de forma segura en HTML


⚠️ VULNERABILIDADES QUE SE MITIGAN
══════════════════════════════════════════════════════════════════════════════

INYECCIÓN SQL:
  ❌ VULNERABLE: "SELECT * FROM users WHERE name = '" + userInput + "'"
  ✅ PROTEGIDO: cmd.Parameters.AddWithValue("@name", userInput)
  
XSS (Cross-Site Scripting):
  ❌ VULNERABLE: $("#div").html(serverData.description)
  ✅ PROTEGIDO: $("#div").html(encodeHTML(serverData.description))
  
MANIPULACIÓN HTML:
  ❌ VULNERABLE: Confiar en data-id que el usuario cambió
  ✅ PROTEGIDO: Validar permiso del usuario en servidor
  
CARGA DE SCRIPTS MALICIOSOS:
  ❌ VULNERABLE: Sin CSP, se pueden cargar scripts de cualquier sitio
  ✅ PROTEGIDO: CSP define qué scripts pueden ejecutarse
