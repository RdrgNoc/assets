1️⃣ Incluir el Archivo de Seguridad

Primero, agrega el archivo de seguridad a tu HTML. Debe cargarse ANTES de otros scripts:

<!-- En el <head> o antes de otros scripts --> <script src="/Content/assets/js/securityHelper.js"></script> <!-- LUEGO tus otros scripts --> <script src="/Content/assets/js/apiHelper.js"></script> <script src="/Content/assets/js/modifiers/controllers/automata-slayer.js"></script>

2️⃣ Sanitización y Validación de Entradas (Prevención de Inyección SQL y XSS)

¿Por qué es importante?

La sanitización y validación evitan que usuarios malintencionados inyecten código malicioso.

Funciones disponibles:

Función Descripción Ejemplo
sanitizeInput(text) Elimina caracteres peligrosos de una cadena sanitizeInput("'; DROP TABLE--") → "DROP TABLE"
isValidNumber(value, min, max) Valida que sea número dentro de rango isValidNumber(2025, 2020, 2030) → true
isValidEmail(email) Valida formato de email isValidEmail("user@example.com") → true
isAlphanumeric(text) Solo letras, números, guiones isAlphanumeric("ABC-123") → true
isValidDate(date) Valida formato YYYY-MM-DD isValidDate("2025-02-18") → true

Ejemplo: Validación de entrada de usuario

❌ ANTES (Vulnerable):
// Esto es inseguro - el usuario puede inyectar SQL var nombreUsuario = $("#txtNombre").val(); var datos = { nombre: nombreUsuario }; fetchDataArr(0, datos, 9, function(response) { ... });
✅ DESPUÉS (Seguro):
// Definir reglas de validación const rules = { nombre: { type: 'string', required: true, minLength: 3, maxLength: 50 } }; // Obtener y validar entrada const input = { nombre: $("#txtNombre").val() }; const validation = validateAndPrepareData(input, rules); if (!validation.valid) { showMsg(validation.errors.join(', '), 'error'); return; } // Si es válido, enviar al servidor const secureData = prepareSecureData( validation.data, AUTOMATA_SLAYER_VERSION ); fetchDataArr(0, secureData, 9, function(response) { ... });

3️⃣ Codificación de Salida (Output Encoding)

¿Por qué es importante?

Al mostrar datos en HTML, CSS, JavaScript o URLs, deben estar codificados para prevenir XSS (Cross-Site Scripting).

Funciones disponibles:

Función Uso Ejemplo
encodeHTML(text) Mostrar texto en HTML encodeHTML("<script>") → "&lt;script&gt;"
encodeAttribute(text) Usar en atributos HTML encodeAttribute('data"test') → 'data"test'
encodeURL(url) Codificar parámetros URL encodeURL("user@test") → "user%40test"

Ejemplo: Mostrar datos de usuario de forma segura

❌ ANTES (Vulnerable a XSS):
// Si el servidor devuelve datos no confiables fetchDataArr(1, {...}, 9, function(response) { // ¡PELIGRO! Si response contiene <script>, se ejecutará $("#contenedor").html(response[0].descripcion); });
✅ DESPUÉS (Seguro):
// Codificar la salida antes de mostrarla fetchDataArr(1, {...}, 9, function(response) { const descripcionSegura = encodeHTML(response[0].descripcion); $("#contenedor").text(descripcionSegura); // O si necesitas HTML, usar un conjunto limitado de etiquetas permitidas });

4️⃣ Content Security Policy (CSP)

¿Qué es CSP?

CSP es una política de seguridad que controla qué recursos (scripts, estilos, imágenes) puede cargar tu página.

Implementación en el servidor (RECOMENDADO)

Esta es la forma más efectiva. Tu desarrollador backend debe agregar este header HTTP:

Para ASP.NET / C#:
// En Global.asax o en Response filters Response.Headers.Add("Content-Security-Policy", "default-src 'self'; " + "script-src 'self' 'unsafe-inline' cdnjs.cloudflare.com code.jquery.com; " + "style-src 'self' 'unsafe-inline' cdnjs.cloudflare.com; " + "img-src 'self' data: https:; " + "font-src 'self' fonts.gstatic.com; " + "connect-src 'self' https:; " + "frame-ancestors 'none'; " + "base-uri 'self'; " + "form-action 'self';" );

Implementación en HTML (Alternativa)

Si no puedes modificar el servidor, puedes usar un meta tag (menos seguro):

<!-- En el <head> --> <meta http-equiv="Content-Security-Policy" content=" default-src 'self'; script-src 'self' 'unsafe-inline' cdnjs.cloudflare.com; style-src 'self' 'unsafe-inline'">

Monitorear violaciones de CSP en JavaScript:

// Llamar esta función una sola vez, al cargar $(document).ready(function() { monitorCSPViolations(); }); // Esto registrará en la consola cualquier violación de CSP detectada

5️⃣ Ejemplos Prácticos Completos

Ejemplo 1: Formulario de Alineación Seguro

function guardarAlineacionSegura() { // Definir reglas de validación const rules = { _idAlineacion: { type: 'number', required: true, min: 1 }, _txtAlineacion: { type: 'string', required: true, minLength: 5, maxLength: 500 }, _eFiscal: { type: 'string', required: true, pattern: /^\d{4}$/ } }; // Obtener datos del formulario const formData = { _idAlineacion: $("#cboAlineacion").val(), _txtAlineacion: $("#txtAlineacion").val(), _eFiscal: $("#cboEfiscal").val() }; // Validar datos const validation = validateAndPrepareData(formData, rules); if (!validation.valid) { validation.errors.forEach(error => { logger.error(error); }); showMsg(validation.errors.join(' | '), 'error'); return; } // Preparar datos seguros const secureData = prepareSecureData( validation.data, AUTOMATA_SLAYER_VERSION ); // Enviar al servidor fetchDataArr(5, secureData, 9, function(response) { if (response.flag) { showMsg('Alineación guardada correctamente', 'success'); } else { showMsg(response.msg, 'error'); } }); }

Ejemplo 2: Mostrar Datos de Forma Segura

// Función para crear tarjetas de riesgo de forma segura function mostrarRiesgosSeguro(riesgos) { let html = ''; riesgos.forEach(riesgo => { // CODIFICAR todos los datos que vienen del servidor const descripcionSegura = encodeHTML(riesgo.DESC_RIESGO); const procesoSeguro = encodeHTML(riesgo.NombreProceso); const nivelSeguro = encodeHTML(riesgo.DESC_NIVEL_RIESGO); html += ` <div class='card'> <div class='card-body'> <h5 class='card-title'>${descripcionSegura}</h5> <p class='card-text'>Proceso: ${procesoSeguro}</p> <p class='card-text'>Nivel: ${nivelSeguro}</p> </div> </div> `; }); $("#containerRiesgos").html(html); }

6️⃣ Checklist de Seguridad

Antes de deployar a producción:

✅ File securityHelper.js está incluido en la página HTML

✅ Todas las entradas de usuario son validadas con validateAndPrepareData()

✅ Todos los datos mostrados en HTML están codificados con encodeHTML()

✅ Los datos en atributos HTML están codificados con encodeAttribute()

✅ Las URLs generadas están codificadas con encodeURL()

✅ CSP está configurado en el servidor (headers HTTP)

✅ Monitoreo de CSP activo con monitorCSPViolations()

✅ El servidor valida TODOS los datos recibidos

✅ El servidor rechaza datos con versión de archivo incorrecta

✅ Se usan HTTPS (no HTTP) en producción

✅ Se han eliminado logs sensibles de la consola

✅ Se han probado ataques XSS y SQL injection
